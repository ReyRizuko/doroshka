# Каталог Doroshka Music через GitHub Releases

Этот вариант не требует VPS, Cloudflare, R2, D1, Docker или банковской карты. Публичный GitHub-репозиторий хранит аудиофайлы во вложениях Releases, а приложение читает список релизов через GitHub API.

## 1. Подготовь репозиторий

Нужен **публичный** репозиторий GitHub. Можно использовать отдельный репозиторий только для музыкального каталога. Приватные репозитории без авторизации приложение прочитать не сможет.

В приложении открой «Обзор» → «Настройки источников» → «Подключить каталог Doroshka Music через GitHub». Введи адрес в формате:

```
ReyRizuko/doroshka
```

Нажми «Сохранить», затем «Проверить». Приложение покажет число найденных аудиофайлов и релизов.

## 2. Добавь первый релиз

1. Открой нужный репозиторий на GitHub.
2. Перейди в **Releases**.
3. Нажми **Create a new release**.
4. В поле **Choose a tag** создай уникальный тег, например `music-001`.
5. В **Release title** укажи название трека, если добавляешь один файл. Если добавляешь несколько треков, укажи название альбома или сборника.
6. В описание релиза добавь метаданные — по одному на строку:

```text
Artist: Имя исполнителя
Album: Название альбома
Genre: Жанр
License: CC BY 4.0
Attribution: Автор, ссылка на оригинал и условия лицензии
Duration: 214
```

`Duration` — длительность в секундах. Она используется, если в релизе один аудиофайл. Для релиза с несколькими треками длительность пока не задаётся отдельно.

7. В блок **Attach binaries by dropping them here or selecting them** добавь аудиофайл или несколько файлов.
8. Необязательно добавь обложку в формате JPG, PNG или WebP.
9. Нажми **Publish release**.

Приложение распознаёт MP3, M4A, AAC, OGG, OPUS, FLAC и WAV. Обложка распознаётся по расширению JPG/JPEG/PNG/WebP.

## 3. Как формируются названия

- Если в релизе один аудиофайл, названием трека будет заголовок релиза.
- Если в релизе несколько аудиофайлов, названия берутся из имён файлов без расширения.
- Исполнитель, альбом, жанр, лицензия и атрибуция берутся из описания релиза.
- Если добавлена картинка, она используется как обложка для треков этого релиза.

Для нескольких треков называй файлы понятно, например `01 - Track Name.mp3`.

## 4. Обнови каталог в приложении

После публикации релиза вернись в приложение и запусти поиск. Каталог автоматически читается из GitHub Releases; обычно достаточно подождать несколько минут или нажать «Проверить».

## Ограничения

- Репозиторий должен быть публичным.
- GitHub API без авторизации имеет лимит запросов; приложение кеширует список релизов на несколько минут.
- GitHub Releases не является специализированным музыкальным хостингом или безлимитным CDN. Не используй этот способ для массовой раздачи больших каталогов.
- Загружай только аудиозаписи, которые ты создал или на распространение которых у тебя есть разрешение. Не используй Releases для копирования коммерческих каталогов Spotify, VK, Apple Music и других платформ.
- Прямое воспроизведение и перемотку на конкретном устройстве нужно проверить после первой загрузки. Веб-ссылка на файл может открываться, даже если конкретный браузер или Android WebView ведёт себя иначе при перемотке.
