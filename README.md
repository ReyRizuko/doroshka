# Дорожка

Android-плеер с локальной медиатекой, очередью воспроизведения, фоновым управлением, Android MediaSession, эквалайзером и импортом плейлистов Spotify (CSV/JSON).

## Музыкальные источники

| Источник | Что реально работает |
|---|---|
| Doroshka Music | Собственный каталог на отдельном сервере. После настройки URL ищет и воспроизводит записи, загруженные с разрешением на распространение. По умолчанию каталог пустой. |
| Audius | Дополнительный открытый источник через официальный API. Не является основой собственного каталога и не равен по составу Spotify, Apple Music или VK Музыке. |
| Internet Archive | Поиск архивных аудиозаписей, просмотр MP3-файлов и потоковое воспроизведение. Это архив, а не коммерческий каталог новых релизов. |
| YouTube | Поиск через YouTube Data API v3 при наличии API key. Видео воспроизводится в официальном встроенном YouTube-плеере, не как фоновый аудиопоток «Дорожки». |
| Spotify, Apple Music, Яндекс Музыка, SoundCloud, Deezer, Bandcamp, VK Музыка | Открытие официального поиска в соответствующем сервисе. Стороннее приложение не получает автоматически права на воспроизведение полного каталога платформы. |

«Дорожка» не извлекает защищённые потоки, не обходит подписки и не использует неофициальные методы доступа. Для каталога коммерческих релизов нужен официальный договор или разрешённый API-доступ соответствующей платформы. Spotify Development Mode с 2026 года ограничен Premium-аккаунтом владельца приложения и небольшим числом авторизованных пользователей; Web API не является разрешением на воспроизведение полного каталога в стороннем плеере.

## YouTube API

1. Создайте проект в Google Cloud Console: https://console.cloud.google.com/
2. Включите YouTube Data API v3.
3. Создайте API key и ограничьте его использованием YouTube Data API.
4. В приложении откройте «Обзор» → «Настройки источников» и сохраните ключ.

## Сборка APK

GitHub Actions собирает APK в workflow **Build APK**. Артефакт называется `dorozhka-apk`; внутри находится `app-debug.apk`.

## Локальная сборка

Нужны Node.js 20+, JDK 21 и Android SDK:

```sh
npm install
npm run android
npx cap open android
```


## Doroshka Music — собственный каталог и API

В репозитории добавлен отдельный backend в `music-server/`. Он не использует Audius или Internet Archive: записи хранятся на сервере, метаданные — в SQLite, аудио отдаётся напрямую с поддержкой HTTP Range (перемотка).

### Возможности API

- `GET /api/v1/health` — проверка доступности сервера.
- `GET /api/v1/search?q=...` — поиск по названию, исполнителю, альбому и жанру.
- `GET /api/v1/tracks/:id` — карточка трека.
- `GET /api/v1/tracks/:id/stream` — аудиопоток с поддержкой Range.
- `POST /api/v1/admin/tracks` — загрузка записи администратором.

### Каталог без VPS и банковской карты

Основной вариант теперь использует **GitHub Releases** как хранилище аудиофайлов. Отдельный сервер, Cloudflare R2/D1, VPS, Docker и банковская карта не нужны. Приложение читает список публичных Releases через GitHub API и воспроизводит прикреплённые аудиофайлы.

Настройка и формат релизов описаны в [releases/README.md](releases/README.md). В приложении укажи публичный репозиторий в формате `владелец/репозиторий`, например `ReyRizuko/doroshka`, затем нажми «Проверить».

GitHub Releases имеет ограничения и не является безлимитным музыкальным CDN. Используй его для небольшого каталога и только для аудиозаписей, которые разрешено распространять.

### Другие варианты backend

Старый backend FastAPI в `music-server/` и экспериментальная конфигурация Cloudflare в `cloudflare/` сохранены как альтернативы. Для текущего варианта Doroshka Music они не требуются.

### Добавление музыки

Пример загрузки записи, права на распространение которой у вас есть:

```sh
curl -X POST http://localhost:8000/api/v1/admin/tracks \
  -H "Authorization: Bearer $DOROZHKA_ADMIN_TOKEN" \
  -F "title=Название трека" \
  -F "artist=Исполнитель" \
  -F "album=Альбом" \
  -F "genre=Жанр" \
  -F "license=CC BY 4.0" \
  -F "attribution=Автор и ссылка на лицензию" \
  -F "file=@track.mp3;type=audio/mpeg"
```

Каталог после первого запуска пустой — это ожидаемо. Сервер не скачивает чужие каталоги и не подменяет лицензию. Загружать можно только записи, для которых есть разрешение на хранение и распространение. У каждой записи сохраняются сведения о лицензии и атрибуции.

### Текущий статус интеграции

Frontend-адаптер подключён к общему поиску и существующему плееру. В настройках источников можно сохранить URL backend и проверить его доступность. Для реального поиска и воспроизведения сервер необходимо развернуть отдельно и наполнить разрешёнными записями. Без URL и загруженной музыки собственный каталог остаётся пустым; Audius и Internet Archive продолжают работать отдельно.
