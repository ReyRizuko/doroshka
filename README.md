# Дорожка

Android-платформа для личной музыкальной коллекции: локальная медиатека, единый поиск по подключённым каталогам, подборки по настроению, избранное, история прослушивания, очередь, фоновое управление, Android MediaSession, эквалайзер и импорт плейлистов Spotify (CSV/JSON).

## Музыкальные источники

### Собственный каталог Doroshka Music

Приложение поддерживает отдельный self-hosted каталог. Укажи адрес своего API в «Настройки источников» → «Мой каталог · Doroshka Music». Backend в `cloudflare/` или `music-server/` предоставляет `/api/v1/health`, `/api/v1/search` и поток `/api/v1/tracks/:id/stream` с поддержкой HTTP Range. Загружай только музыку, на которую есть права или разрешение на распространение. URL API хранится локально на устройстве; администраторский токен не встраивается в приложение. Для публичного сервера настрой HTTPS и CORS.


### Apple Music и Spotify

В общий поиск добавлены официальные каталоги Apple Music и Spotify. Результаты этих сервисов можно добавлять в общую очередь и управлять ими через единый экран «Сейчас играет» в поддерживаемых браузерах.

**Apple Music**
1. Нужен Apple Music Developer Token (JWT), созданный для Apple Music API.
2. В приложении открой «Обзор» → «Настройки источников» → «Apple Music» и вставь токен.
3. Поиск выполняется по каталогу Apple Music. Для воспроизведения через MusicKit пользователь должен авторизовать свой Apple Music аккаунт; полные треки требуют активной подписки.
4. Токен сохраняется локально в браузере/приложении. Не публикуй его и не отправляй в сообщения.

Документация: https://developer.apple.com/musickit/

**Spotify**
1. Создай приложение в Spotify Developer Dashboard и скопируй Client ID.
2. Для Android укажи Redirect URI `doroshka://spotify-callback` и зарегистрируй его в Spotify Developer Dashboard. Для веб-версии укажи HTTPS-адрес страницы «Дорожки». Redirect URI должен совпадать посимвольно. Spotify продолжает поддерживать custom URI schemes, но для новых интеграций рекомендует HTTPS, где это возможно.
3. Сохрани настройки и нажми «Войти в Spotify». Используется Authorization Code с PKCE, Client Secret в приложении не хранится.
4. Поиск идёт по официальному Spotify Web API. Воспроизведение через Web Playback SDK требует Spotify Premium и поддерживаемого браузера. В Android-приложении встроенный Spotify Playback пока не реализован: приложение не подменяет его открытием внешней ссылки. Смешанная очередь с Apple Music/Spotify пока ограничена веб-версией.

Документация: https://developer.spotify.com/documentation/web-api и https://developer.spotify.com/documentation/web-playback-sdk. Spotify запрещает коммерческие streaming-интеграции без отдельного письменного разрешения; перед публикацией проверь актуальные Developer Terms.

Ни один из этих сервисов не гарантирует наличие абсолютно каждой существующей записи. Доступность зависит от страны, лицензий, подписки и настроек платформы. Приложение не обходит авторизацию, региональные ограничения или DRM.


| Источник | Что реально работает |
|---|---|
| Jamendo | Поиск и потоковое воспроизведение каталога независимых исполнителей по официальному read-only API. Нужен Client ID разработчика; каталог включает треки с Creative Commons-лицензиями. |
| Audius | Дополнительный открытый источник через официальный API. Не является основой собственного каталога и не равен по составу Spotify, Apple Music или VK Музыке. |
| Internet Archive | Поиск архивных аудиозаписей, просмотр MP3-файлов и потоковое воспроизведение. Это архив, а не коммерческий каталог новых релизов. |
| YouTube | Поиск через YouTube Data API v3 при наличии API key. Видео воспроизводится в официальном встроенном YouTube-плеере, не как фоновый аудиопоток «Дорожки». |
| Spotify, Apple Music, Яндекс Музыка, SoundCloud, Deezer, Bandcamp, VK Музыка | Открытие официального поиска в соответствующем сервисе. Стороннее приложение не получает автоматически права на воспроизведение полного каталога платформы. |

«Дорожка» не извлекает защищённые потоки, не обходит подписки и не использует неофициальные методы доступа. Для каталога коммерческих релизов нужен официальный договор или разрешённый API-доступ соответствующей платформы. Общая очередь унифицирует интерфейс и управление, но каждый защищённый сервис сохраняет собственный движок и ограничения лицензии. Spotify Development Mode с 2026 года ограничен Premium-аккаунтом владельца приложения и небольшим числом авторизованных пользователей; Web API не является разрешением на воспроизведение полного каталога в стороннем плеере.

## YouTube API

1. Создайте проект в Google Cloud Console: https://console.cloud.google.com/
2. Включите YouTube Data API v3.
3. Создайте API key и ограничьте его использованием YouTube Data API.
4. В приложении откройте «Обзор» → «Настройки источников» и сохраните ключ.

## Сборка APK

GitHub Actions собирает APK в workflow **Build APK**. Артефакт называется `dorozhka-apk`; внутри находится `app-debug.apk`.

## Локальная сборка

Нужны Node.js 20+, JDK 21 и Android SDK. `npm run check` собирает `www/` из актуального `index.html` и проверяет синтаксис приложения и адаптеров; тот же тест запускается GitHub Actions при изменениях в `feat/multisource-ui`:

```sh
npm install
npm run check
npm run android
npx cap open android
```


## Каталог Jamendo

В репозитории добавлен отдельный backend в `music-server/`. Он не использует Audius или Internet Archive: записи хранятся на сервере, метаданные — в SQLite, аудио отдаётся напрямую с поддержкой HTTP Range (перемотка).

### Возможности API

- `GET /api/v1/health` — проверка доступности сервера.
- `GET /api/v1/search?q=...` — поиск по названию, исполнителю, альбому и жанру.
- `GET /api/v1/tracks/:id` — карточка трека.
- `GET /api/v1/tracks/:id/stream` — аудиопоток с поддержкой Range.
- `POST /api/v1/admin/tracks` — загрузка записи администратором.

### Музыка без ручной загрузки файлов

Jamendo предоставляет read-only API для поиска в каталоге примерно из 500 000 треков. API возвращает аудиопоток и обложки; ручная загрузка файлов, VPS, R2 и D1 не нужны. Для подключения требуется Client ID, который создаётся в developer portal. Для некоммерческих приложений документация указывает read-only доступ и лимит запросов; проверь актуальные условия Jamendo перед публикацией приложения.

В приложении открой «Обзор» → «Настройки источников» → «Подключить каталог Jamendo», вставь Client ID и сохрани. Это каталог независимых исполнителей и Creative Commons, а не полный коммерческий каталог Spotify, VK, Apple Music или Яндекс Музыки.

Официальная документация: https://developer.jamendo.com/v3.0/docs. API terms: https://devportal.jamendo.com/api_terms_of_use.

### Другие варианты backend

Старый backend FastAPI в `music-server/` и экспериментальная конфигурация Cloudflare в `cloudflare/` сохранены как альтернативы. Для текущего варианта Doroshka Music они не требуются.

### Добавление музыки

Пример загрузки записи, права на распространение которой у вас есть:

```sh
curl -X POST http://localhost:8000/api/v1/admin/tracks \
  -H "Authorization: Bearer $DOROZHKA_ADMIN_TOKEN" \
  -F "title=Название трека" \
  -F "artist=Исполнитель" \
  -F "album=Альбом" \
  -F "genre=Жанр" \
  -F "license=CC BY 4.0" \
  -F "attribution=Автор и ссылка на лицензию" \
  -F "file=@track.mp3;type=audio/mpeg"
```

Каталог после первого запуска пустой — это ожидаемо. Сервер не скачивает чужие каталоги и не подменяет лицензию. Загружать можно только записи, для которых есть разрешение на хранение и распространение. У каждой записи сохраняются сведения о лицензии и атрибуции.

### Текущий статус интеграции

Frontend-адаптер Jamendo подключён к общему поиску и существующему плееру. Нужен Client ID. Главный экран включает музыкальные направления, историю и очередь; медиатека поддерживает избранное. Общий поиск параллельно запрашивает Jamendo, Audius, Internet Archive, Apple Music, Spotify и YouTube (последние три требуют настроек/ключей). Результаты можно запускать или добавлять в очередь там, где источник поддерживает потоковое воспроизведение. YouTube остаётся официальным видеоплеером. Реальное воспроизведение и перемотку необходимо проверить на целевом Android-устройстве.
